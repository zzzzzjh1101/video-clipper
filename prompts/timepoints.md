## 通用定位规则

### start_time（开始点）
- 定位到该话题/爆点**第一句核心发言**的开始时间。
- 忽略开头寒暄、口头禅、过渡语（「嗯」「然后」「那什么」）。
- 钩子前置：直播切片前 3 秒必须出现爆点（福利/金句/冲突/悬念）。

### end_time（结束点，最重要）
- 必须是该爆点**最后一句话的结束时间戳**，语义完整、不突兀断点。
- 娱乐类：保留笑点后的反应/笑声/观众反馈。
- 带货类：必须包含价格/福利信息完整说完。
- 知识类：观点抛出 → 论证闭环，一条切片一个知识点。
- 绝不在话说到一半处切断；话题结束后若有总结/过渡句，不包含进 end_time。

### 时长控制
- 默认目标时长：15-60 秒（{{TARGET_DUR}} 秒）。
- 若内容本身是完整长干货（知识类），允许 1-3 分钟。
- 相邻两个候选若语义相关且各自 <20s，可合并为一条。

## 高播放量四维评估（每候选必评）
1. **信息价值**：独特见解 / 信息密度 / 实用 / 反常识
2. **情感共鸣**：爽 / 笑 / 怒 / 好奇 / 共鸣 / 吃瓜
3. **传播潜力**：金句 / 梗 / 争议 / 可讨论 / 可转发
4. **结构完整**：有始有终，起承转合

## 爆点类型标签（type 字段，单选）
金句 | 高能 | 干货 | 争议 | 情绪 | 名场面 | 福利 | 剧情转折 | 互动冲突 | 才艺高光 | 笑点 | 信息差

## 多说话人（时间表中带 [S0]/[S1] 标签时）
- 互动冲突类（PK/连麦/吵架）：保留双方完整交锋，speakers 列出涉及的所有人。
- 单人口播：speakers 为实际说话人。

## 输出格式（严格 JSON，不要 markdown 代码块，不要多余文字）
```json
{
  "clips": [
    {
      "start": 125.4,
      "end": 152.8,
      "type": "金句",
      "score": 0.92,
      "quote": "这段的原话摘录（15-40字）",
      "reason": "推荐理由（15-30字，说人话、有钩子）",
      "title": "切片标题（20字内，平台风格）",
      "speakers": ["S1"]
    }
  ]
}
```

## 硬性要求
- start/end 必须取**时间表中已存在的句子时间**，禁止自创时间。
- 至少给 3 条候选；最多 12 条；按 score 从高到低排序。
- score 是 0-1 的爆款潜力分，全表平均分控制在 0.5 左右（别都打高分）。
- 宁可少而精，不要凑数。
